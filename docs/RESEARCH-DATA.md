# ASX 200 research data map

The screen uses the 200 ASX equity holdings in BlackRock's IOZ portfolio as a current-member proxy. `data/research/universe.json` records the source URL, holdings date, check time, company code, name and sector. It is not a reconstruction of historic index membership, and another year's holdings can differ. The project stores only these identifying fields, not portfolio weights or prices.

`data/research/announcements/<TICKER>.json` holds one record per archive year from 2021 through 2026. Each year records the ASX search URL, retrieval time, number of announcement rows seen, screened headline rows and any error. The 2021 rows start on 23 September, making a five-year lookback from the first collection date. A saved error is not counted as coverage. The collector only saves likely raise headlines and their announcement IDs, not whole ASX pages or PDF contents. Re-running the command skips successfully collected years and retries failures; `--refresh-current-year` checks 2026 again without repeating older years.

`data/research/candidates.json` is rebuilt from the company files. It groups screened titles for one ticker when they are no more than 45 days apart, labels each group unverified and retains the links to every matched source notice. This grouping is a research convenience, not proof the documents belong to one transaction. Generic securities forms, undisclosed raises and unusually titled announcements can be missed; unrelated raises close in time can be combined. The ASX announcement link may lead through ASX's access-terms page before the PDF.

The research record needed for a usable precedent remains separate: a human or evidence-controlled extractor must confirm structure, launch date, amount, offer price, purpose, completion, independent issued-share count and the source location supporting each field. Discount and dilution then need an unaffected price and pre-raise share count. The existing release pipeline in `docs/PIPELINE.md` enforces core evidence before publishing verified transactions. Neither this headline screen nor its rough similarity links enter that release automatically.

`data/research/terms.json` holds the offer terms for each raise, built by `npm run data:terms`. The script opens up to three notices per raise in the order launch announcement, presentation and completion notice, downloads the PDF from announcements.asx.com.au, reads the first twelve pages with pypdf and keeps the offer price, discounts with their basis, underwriting, lead managers, entitlement ratio and the use of funds sentence. Every field stores the notice ID and the sentence it came from, which the homepage shows on hover. PDFs and their text are cached in `.local/terms/`, so `npm run data:terms -- --refresh` re-reads them without downloading again. The extractor is pattern-based, so a term written unusually is left blank and a price for a different security can occasionally be picked up, which is why each value links to its source.

`npm run data:funding` reads every company's yearly announcement archive again, keeps all titles in `.local/archive/` and writes `data/research/funding.json`, which groups convertible notes, hybrids and subordinated notes, bonds, announced loan facilities and royalty or stream deals, with notices for the same instrument within 60 days treated as one deal. Notices about instruments already on issue, such as distribution rates, redemptions and newsletters, are dropped. `npm run data:funding-terms` reads the pricing or launch notice for each deal into `data/research/funding-terms.json` with size, coupon, margin over BBSW, maturity, conversion premium, banks and purpose. `npm run data:market` pulls daily closes, splits, reported share counts and AUD cross rates from Yahoo Finance into `data/research/market.json`, giving each equity raise its pre-raise market cap, size as a share of market cap, the discount implied by the previous close and the share price on day 1 and 20 trading days later against the offer price, and giving each debt deal its A$ size and share of market cap. Halted days, which Yahoo reports with the previous close and no volume, are skipped.

`npm run data:quotes` writes `data/research/quotes.json` with the last available Yahoo Finance close for each company, including the trading date. It is a manually refreshed snapshot, not a live feed. The company model uses that close as a default and leaves shares on issue and gross debt blank because Yahoo's financial series can lag a capital raising by years. Its dilution and debt / total capital calculations only appear after the user enters those figures. A current capital structure and cash-flow assessment still need the issuer's latest ASX filings. The headline structure comparison excludes unresolved raises and announcement groups containing an explicit follow-on placement, since their price and size may describe different issues. Those groups remain accessible in the linked deal list.

Commands:

```bash
npm run data:backfill -- --limit=5
npm run data:backfill -- --ticker=PDN
npm run data:backfill -- --all
npm run data:backfill -- --all --refresh-current-year
npm run data:backfill -- --reindex
npm run data:backfill -- --refresh-universe --limit=5
```

The full run makes up to 1,200 year-by-company requests, spaces them by at least 600 milliseconds and saves each year before moving on. It can resume after interruption. The current holdings source should be reviewed before refreshing the universe because a changed member list alters the project boundary; files for former members are retained but omitted from the current candidate index.
